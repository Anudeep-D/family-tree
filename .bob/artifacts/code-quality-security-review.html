🔍 Code Quality & Security Review

Family Tree Project – Dependency & Vulnerability Analysis

Executive Summary

Found 4 critical issues and 8 high-priority security/modernization concerns. Immediate action required on container base images, Python version, deprecated packages, and network binding.

🚨 CRITICAL ISSUES

1. Python 3.9 EOL – Chatbot Dockerfile

Severity: CRITICAL

chatbot/Dockerfile uses python:3.9-slim which reached End of Life on October 5, 2025. No security patches will be released.

Risk: Vulnerable to unpatched Python vulnerabilities; fails IBM security compliance.

Fix: Update to Python 3.11 (latest stable) using Red Hat UBI minimal image for security compliance: 
FROM registry.redhat.io/ubi9/python-311-minimal:latest

2. Node.js 23 EOL Risk – familyTreeUI Dockerfile

Severity: CRITICAL

familyTreeUI/Dockerfile uses node:23-alpine. Node.js 23 is not LTS and only receives security updates until April 2025.

Risk: EOL soon; rapidly losing security coverage.

Fix: Use LTS version (Node 22): 
FROM node:22-alpine

3. Java Base Image – Not from Trusted Registry

Severity: CRITICAL

familytree/Dockerfile uses eclipse-temurin:17-jdk. IBM security policy requires images from registry.redhat.io (Red Hat UBI).

Risk: Fails IBM container registry compliance; potential supply chain risk.

Fix: Switch to Red Hat UBI8 Java image: 
FROM registry.redhat.io/ubi8/openjdk-17:latest

4. Insecure Network Binding – Chatbot Service

Severity: CRITICAL

chatbot/Dockerfile binds to 0.0.0.0:8000. Exposes service to all interfaces in production.

Risk: Violates IBM network security policy; enables unauthorized external access.

Fix: Bind to localhost only: 
CMD ["uvicorn", "main:app", "--host", "127.0.0.1", "--port", "8000"]

🔐 Security Best Practices – Not Implemented

Container Hardening

  • No non-root USER: All containers run as root. Add USER 1001 before CMD.
  • No read-only root filesystem: Recommend enabling in orchestration layer.
  • No security scanning: No tool to scan built images for vulnerabilities.

Secrets Management

  • Verify .env files are in .gitignore (critical for credentials).
  • Ensure API keys are stored in secure vaults (Hashicorp Vault, IBM Key Protect), not env files.

Network Security

  • No HTTPS enforcement in Nginx config (check nginx/default.conf).
  • No TLS 1.3 enforcement documented.
